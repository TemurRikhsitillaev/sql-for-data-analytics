# SQL для аналитики данных

Конспекты и практика по PostgreSQL — от `SELECT` до оконных функций и упорядоченных агрегатов. Материал собран в ходе подготовки к собеседованию на позицию аналитика данных.

Всё написано и проверено на реальной базе, а не на игрушечных таблицах из двух строк.

---

## База

**Northwind** — классическая учебная база (заказы, товары, клиенты, сотрудники, поставщики) плюс дописанный поверх неё аналитический слой:

| Таблица | Что внутри |
|---|---|
| `users` | пользователи: канал привлечения, устройство, страна, дата регистрации |
| `sessions` | сессии пользователей |
| `events` | события: `view_product`, `add_to_cart`, покупки — с привязкой к сессии и товару |
| `ab_assignments` | распределение пользователей по группам A/B-тестов |
| `web_orders`, `web_order_items` | веб-заказы и их позиции |
| `reviews` | отзывы на товары |

Классическая часть Northwind нужна для джойнов и агрегатов, аналитический слой — для воронок, конверсий и когортных задач, которые на собеседованиях спрашивают чаще всего.

## Порядок выполнения запроса

Главное, что нужно держать в голове: SQL **пишется** не в том порядке, в каком **выполняется**.

```
FROM → WHERE → GROUP BY → HAVING → [оконные функции] → SELECT → DISTINCT → ORDER BY → OFFSET → LIMIT
```

Отсюда растёт половина правил языка:

- алиас из `SELECT` **не виден** в `WHERE`, `GROUP BY` и `HAVING` — они выполняются раньше;
- алиас **виден** в `ORDER BY` — он выполняется позже;
- оконную функцию нельзя положить в `WHERE` — на момент фильтрации её ещё нет, нужен CTE или внешний запрос;
- `LIMIT` применяется в самом конце, ко всему результату, поэтому «топ-3 в каждой группе» через `LIMIT` не делается.

## Чему учат разборы

Содержательная часть — не в том, что такое `JOIN`, а в ошибках, которые дают **правдоподобный, но неверный** результат. Такие ошибки не падают с эксепшеном, их не видно в выдаче, и именно они стоят дорого:

- `COUNT(*)` после джойна «один-ко-многим» считает позиции, а не заказы;
- `o.order_id = o.order_id` в `ON` — опечатка в один символ, превращающая `JOIN` в `CROSS JOIN`;
- `NOT IN` с подзапросом, где встречается `NULL`, возвращает пустой результат;
- деление `integer / integer` молча отбрасывает дробную часть;
- `LEFT JOIN` + условие на правую таблицу в `WHERE` вместо `ON` — джойн превращается во внутренний;
- `EXTRACT(MONTH ...)` вместо `DATE_TRUNC` — месяцы разных лет схлопываются в один;
- запрос без `ORDER BY` возвращает строки в неопределённом порядке, и на маленькой таблице это может случайно выглядеть правильно.

Каждая из них разобрана в конспекте соответствующей темы.
