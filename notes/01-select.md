# SELECT: выборка, алиасы, DISTINCT, ORDER BY, LIMIT

## Порядок выполнения

Запрос пишется в одном порядке, а выполняется в другом. Это не формальность — из порядка выполнения следует половина правил языка.

```
FROM → WHERE → GROUP BY → HAVING → [оконные функции] → SELECT → DISTINCT → ORDER BY → OFFSET → LIMIT
```

Сначала СУБД находит источник данных, потом фильтрует строки, потом группирует, потом считает, что показать, и только в конце сортирует и отрезает нужное количество.

Отсюда:

- алиас, объявленный в `SELECT`, **не виден** в `WHERE` — `WHERE` выполнился раньше;
- алиас **виден** в `ORDER BY` — он выполняется позже `SELECT`;
- `LIMIT` применяется к уже отсортированному результату, последним шагом.

---

## Базовый синтаксис

```
SELECT [DISTINCT] выражение [AS алиас] [, ...]
FROM таблица
[ORDER BY выражение [ASC | DESC] [NULLS FIRST | NULLS LAST] [, ...]]
[LIMIT количество] [OFFSET пропустить]
```

Квадратные скобки — необязательная часть, вертикальная черта — выбор одного из вариантов, `[, ...]` — элемент можно повторить через запятую. Сами скобки и черта в запрос не пишутся.

```sql
SELECT first_name, last_name, title FROM employees;
SELECT * FROM categories;
```

`*` берёт все колонки. Удобно для разведки, но в рабочих запросах его не оставляют: при изменении схемы результат меняется молча, а лишние колонки тянут данные зря.

## Выражения и алиасы

В `SELECT` можно писать не только имена колонок, но и вычисления:

```sql
SELECT product_name,
    ROUND((unit_price * 0.85)::numeric, 2) AS sale_price
FROM products;
```

`AS` можно опустить — `unit_price sale_price` сработает, — но с `AS` читается яснее.

**Ловушка со скидкой.** «Цена со скидкой 15%» — это `unit_price * 0.85`, а не `unit_price * 0.15`. Второе даёт размер скидки, а не цену. Ошибка не падает и выглядит правдоподобно.

### Конкатенация

```sql
SELECT last_name || ', ' || first_name AS "Сотрудник"
FROM employees
ORDER BY last_name;
```

`||` склеивает строки. Если хотя бы один операнд `NULL`, результат весь `NULL` — защищают через `COALESCE`.

## Кавычки

| Кавычки | Для чего | Пример |
|---|---|---|
| `'одинарные'` | **значения**: строки и даты | `WHERE country = 'Germany'` |
| `"двойные"` | **идентификаторы**: имена колонок, таблиц, алиасов | `AS "Цена, $"` |
| `` `обратные` `` | в PostgreSQL **не работают** | — |

```sql
SELECT product_name AS "Название товара",
       unit_price  AS "Цена, $"
FROM products;
```

Двойные кавычки нужны, когда в имени есть пробел, кириллица, спецсимвол или заглавные буквы. Без кавычек PostgreSQL приводит все идентификаторы к нижнему регистру: `Product_Name` и `product_name` — одно и то же, а `"Product_Name"` — другое, и такой колонки в таблице нет.

**Апостроф внутри строки** удваивается:

```sql
SELECT product_name, 'Northwind''s catalog' AS "Источник" FROM products;
```

Типичные ошибки:

```sql
SELECT unit_price AS 'Цена' FROM products;  -- ошибка: '' только для значений
SELECT "Product_Name" FROM products;        -- ошибка: нет такой колонки, регистр важен
```

## Приведение типов: `::numeric`

В PostgreSQL несколько числовых типов, и они ведут себя по-разному.

| Тип | Что это | Особенность |
|---|---|---|
| `integer`, `bigint` | целые | деление целых даёт целое |
| `real`, `double precision` | с плавающей точкой | быстро, но неточно для денег |
| `numeric` / `decimal` | точное десятичное | для денег и процентов |

Узнать тип: `SELECT pg_typeof(unit_price) FROM products LIMIT 1;`

### Деление целых

```sql
SELECT units_in_stock / reorder_level,            -- 2  (целочисленное)
       units_in_stock::numeric / reorder_level    -- 2.3333...
FROM products
WHERE reorder_level <> 0;
```

`integer / integer` в PostgreSQL даёт `integer` — дробная часть **отбрасывается**, не округляется.

**Ключевое правило:** приводить нужно **до** деления, а не после.

```sql
(units_in_stock / reorder_level)::numeric   -- 2.0000  — дробь уже потеряна
units_in_stock::numeric / reorder_level     -- 2.3333  — верно
```

Достаточно привести **один** операнд: второй повысится до того же типа автоматически.

### Когда нужен `::numeric`

- `ROUND(x, 2)` с двумя аргументами существует только для `numeric`. Для `real`/`double precision` нужен каст: `ROUND(AVG(unit_price)::numeric, 2)`.
- Деление, где важна дробная часть.
- Любые деньги и проценты.

Форма `CAST(x AS numeric)` — то же самое в стандартном SQL-синтаксисе.

## DISTINCT

Убирает повторы **по всей строке результата**, а не по первой колонке.

```sql
SELECT DISTINCT ship_city FROM orders ORDER BY ship_city;

SELECT DISTINCT country, city FROM customers ORDER BY country, city;
```

Второй запрос даёт уникальные **пары** «страна + город». Один и тот же город появится дважды, если он есть в двух странах; одна и та же страна появится много раз — с разными городами.

### DISTINCT ON

Расширение PostgreSQL: оставляет **одну строку на каждое значение** указанных колонок.

```sql
SELECT DISTINCT ON (category_id) category_id, product_name, unit_price
FROM products
ORDER BY category_id, unit_price DESC;
```

Правила:

1. `ORDER BY` **обязан** начинаться с тех же выражений, что в `DISTINCT ON`.
2. Остальные выражения `ORDER BY` решают, **какая именно** строка останется.

Без `ORDER BY` вернётся произвольная строка из группы — запрос отработает, но результат будет недетерминированным. Это тихая ошибка: сегодня один товар, завтра другой.

```sql
-- самый свежий заказ по каждой стране
SELECT DISTINCT ON (ship_country) ship_country, order_id, order_date
FROM orders
ORDER BY ship_country, order_date DESC, order_id DESC;
```

`order_id DESC` — тай-брейк: если в один день два заказа, выбор станет однозначным.

## ORDER BY

```sql
SELECT product_name, category_id, unit_price
FROM products
ORDER BY category_id, unit_price DESC;
```

По умолчанию `ASC` (по возрастанию). Сортировка по нескольким колонкам: вторая применяется внутри групп с одинаковой первой.

### NULL в сортировке

По умолчанию в PostgreSQL:

- `ASC` → `NULLS LAST`
- `DESC` → `NULLS FIRST`

То есть `NULL` считается «самым большим». Переопределяется явно:

```sql
SELECT order_id, order_date, shipped_date
FROM orders
ORDER BY shipped_date DESC NULLS LAST;
```

**Частая ошибка.** Задача «сначала неотправленные, потом остальные по дате» решается не через `NULLS FIRST`, а через отдельный сортировочный ключ:

```sql
ORDER BY (shipped_date IS NULL) DESC, order_date
```

`shipped_date IS NULL` даёт `true`/`false`; `true > false`, поэтому `DESC` поднимает неотправленные наверх. А `order_date` сортирует внутри каждой из двух групп. Через `NULLS FIRST` этого не получить — он влияет только на положение `NULL` внутри сортировки по самой колонке.

### Сравнение строк

```sql
WHERE product_name >= 'A' AND product_name < 'H'
```

Строки сравниваются лексикографически, посимвольно, по правилам локали базы. `'H'` без букв после себя меньше любого `'Ha...'`, поэтому `< 'H'` берёт все названия на A–G включительно, а `'Hello'` отсекает. Это надёжнее, чем `IN ('A','B',...,'G')` — тот сравнивает строку целиком и совпадёт только с названием ровно «A».

## LIMIT и OFFSET

```sql
SELECT product_name, unit_price FROM products ORDER BY unit_price LIMIT 3;
```

`LIMIT` без `ORDER BY` бессмысленен: порядок строк не определён, и «первые три» каждый раз могут быть разными.

`OFFSET` пропускает строки **до** применения `LIMIT`:

```
... ORDER BY ... OFFSET 20 LIMIT 10
```

Пагинация: страница N по 10 записей → `LIMIT 10 OFFSET 10 * (N - 1)`.

```sql
SELECT * FROM products ORDER BY product_name LIMIT 10 OFFSET 20;  -- третья страница
```

В порядке выполнения `OFFSET` идёт **перед** `LIMIT`: сначала отбрасываются строки, потом из остатка берётся нужное количество.

## Чек-лист ошибок

| Симптом | Причина |
|---|---|
| Дробная часть потерялась | Каст после деления, а не до: `(a/b)::numeric` вместо `a::numeric / b` |
| `ROUND` ругается на два аргумента | Аргумент не `numeric` — нужен `::numeric` |
| Результат меняется между запусками | `DISTINCT ON` или `LIMIT` без детерминированного `ORDER BY` |
| «Свежие» записи оказались не свежими | Сортировка по `id` вместо даты |
| Ошибка «column does not exist» | Идентификатор в одинарных кавычках или в двойных с неверным регистром |
| Строка целиком `NULL` после `||` | Один из операндов `NULL` — нужен `COALESCE` |
