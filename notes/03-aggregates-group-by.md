# Агрегаты, GROUP BY, HAVING, FILTER

## Агрегатные функции

Агрегат сворачивает множество строк в одно значение.

| Функция | Что делает | NULL |
|---|---|---|
| `COUNT(*)` | количество строк | считает все строки |
| `COUNT(col)` | количество непустых значений | **пропускает `NULL`** |
| `COUNT(DISTINCT col)` | количество разных непустых значений | пропускает `NULL` |
| `SUM(col)` | сумма | пропускает `NULL`; если все `NULL` → `NULL`, не 0 |
| `AVG(col)` | среднее | пропускает `NULL` — делит на число непустых |
| `MIN`, `MAX` | минимум, максимум | пропускают `NULL` |

### COUNT(*) против COUNT(col)

Это самое важное различие в теме.

```sql
SELECT COUNT(*)                AS total,        -- все товары
       COUNT(units_in_stock)   AS with_stock,   -- у кого остаток не NULL
       COUNT(DISTINCT category_id) AS categories
FROM products;
```

«Сколько всего товаров» — это `COUNT(*)`. Если написать `COUNT(units_in_stock)`, ответ будет меньше ровно на число строк с `NULL`, и ошибку не видно: число выглядит правдоподобно.

### AVG и NULL

`AVG` делит сумму на количество **непустых** значений, а не на количество строк. Если нужно считать `NULL` как ноль:

```sql
AVG(COALESCE(freight, 0))
```

Это разные метрики, и выбор между ними — содержательное решение, а не вопрос стиля.

## GROUP BY

```sql
SELECT category_id,
       COUNT(*)            AS products_count,
       ROUND(AVG(unit_price)::numeric, 2) AS avg_price
FROM products
GROUP BY category_id
ORDER BY products_count DESC;
```

Правило: **каждая колонка в `SELECT` должна быть либо в `GROUP BY`, либо под агрегатом.** Иначе СУБД не знает, какое из многих значений показать, и выдаёт ошибку.

Исключение: если в `GROUP BY` стоит первичный ключ, остальные колонки той же таблицы можно не перечислять — они функционально зависимы.

```sql
GROUP BY c.category_id, c.category_name   -- так надёжнее и работает везде
```

### Позиционная запись

```sql
GROUP BY 1
```

Число — **порядковый номер колонки в `SELECT`**, нумерация с единицы. `GROUP BY 1` группирует по первому выражению списка. `GROUP BY 0` — ошибка, нулевой колонки не существует; номер больше количества колонок — тоже ошибка.

Удобно, когда первая колонка — длинное выражение вроде `DATE_TRUNC('month', order_date)::date`. Минус: при перестановке колонок запрос молча начнёт группировать по другому полю. То же работает в `ORDER BY`. В одном запросе лучше держать один стиль — либо везде номера, либо везде имена.

## HAVING

`WHERE` фильтрует строки **до** группировки, `HAVING` — группы **после**.

```sql
SELECT country, COUNT(*) AS orders_count
FROM orders
GROUP BY country
HAVING COUNT(*) >= 10
ORDER BY orders_count DESC;
```

В `HAVING` алиас тоже не виден (он объявляется в `SELECT`, который выполняется позже) — поэтому агрегат пишется заново.

Порядок: `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`.

Если условие можно проверить до группировки — ставь его в `WHERE`: так отфильтруется меньше данных и запрос будет быстрее. `HAVING` нужен только для условий на результат агрегата.

**«Минимум 5»** — это `>= 5`, а не `> 5`. На границах теряется ровно одна группа.

## FILTER — условные агрегаты

Нативный для PostgreSQL способ посчитать несколько срезов в одной строке:

```sql
SELECT
    COUNT(*)                                   AS total,
    COUNT(*) FILTER (WHERE shipped_date IS NOT NULL) AS shipped,
    COUNT(*) FILTER (WHERE shipped_date IS NULL)     AS not_shipped,
    SUM(freight) FILTER (WHERE ship_country = 'Germany') AS freight_germany
FROM orders;
```

Читается как «посчитай, но только по строкам, где выполняется условие».

Классический аналог — агрегат от `CASE`:

```sql
COUNT(*) FILTER (WHERE discontinued = 1)          -- так
COUNT(CASE WHEN discontinued = 1 THEN 1 END)      -- то же самое, длиннее
SUM(CASE WHEN discontinued = 1 THEN 1 ELSE 0 END) -- и так тоже
```

`FILTER` читается яснее и работает с любым агрегатом. `CASE` внутри агрегата — переносимый вариант для СУБД, где `FILTER` нет.

При счёте через `COUNT(CASE ...)` важно помнить: `COUNT` считает непустые значения, поэтому ветка `ELSE` не нужна — без неё `CASE` вернёт `NULL`, и строка не посчитается. А вот `SUM(CASE ... ELSE 0 END)` требует `ELSE 0`.

## Округление агрегатов

```sql
ROUND(SUM(unit_price * quantity)::numeric, 2)   -- верно
SUM(ROUND((unit_price * quantity)::numeric, 2)) -- неверно
```

Во втором варианте округляется каждое слагаемое, и копеечные погрешности накапливаются по всем строкам. Округлять нужно **результат**, а не входы.

## Чек-лист ошибок

| Симптом | Причина |
|---|---|
| `column must appear in the GROUP BY clause` | Колонка в `SELECT` не сгруппирована и не под агрегатом |
| Количество меньше ожидаемого | `COUNT(col)` вместо `COUNT(*)` — пропущены `NULL` |
| Среднее выше ожидаемого | `AVG` делит на число непустых, а не на число строк |
| Сумма отличается на копейки | Округление внутри `SUM` вместо округления результата |
| В топе не то, что нужно | Забыт `DESC` в `ORDER BY` |
| Пропала одна группа | `>` вместо `>=` на границе «минимум N» |
| `SUM` вернул `NULL`, а не 0 | Все слагаемые `NULL` — нужен `COALESCE(SUM(x), 0)` |
