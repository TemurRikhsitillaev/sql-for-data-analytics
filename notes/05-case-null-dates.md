# CASE, NULL-функции и даты

## CASE

### Полная форма

```sql
CASE
    WHEN unit_price < 10 THEN 'budget'
    WHEN unit_price <= 50 THEN 'medium'
    ELSE 'premium'
END AS segment
```

Условия проверяются **сверху вниз**, срабатывает первое истинное. Поэтому второе условие не нужно писать как `unit_price >= 10 AND unit_price <= 50` — до него доходят только строки, не прошедшие первую проверку.

Без `ELSE` непопавшие строки получают `NULL`. Это умолчание, а не ошибка — иногда именно то, что нужно.

### Короткая форма

```sql
CASE discontinued
    WHEN 0 THEN 'в продаже'
    WHEN 1 THEN 'снят'
END
```

Работает только для сравнения на равенство с одним выражением. Для диапазонов и сложных условий — полная форма.

### Упрощение

Если каждая ветка возвращает что-то простое, часто `CASE` не нужен вовсе:

```sql
CASE WHEN x > 0 THEN 'рост' WHEN x < 0 THEN 'падение' ELSE 'без изменений' END
```

— тут нужен. А вот это:

```sql
CASE WHEN shipped_date IS NULL THEN true ELSE false END
```

— то же самое, что `shipped_date IS NULL`. Сравнение само по себе уже даёт булево значение.

## COALESCE

Возвращает первый аргумент, не равный `NULL`.

```sql
COALESCE(region, 'не указан')
COALESCE(acquisition_channel, 'unknown')
COALESCE(SUM(amount), 0)
```

Аргументов может быть сколько угодно: `COALESCE(a, b, c, 'default')`.

**Когда `COALESCE` уместен, а когда вреден.** Подмена `NULL` на ноль правильна, если ноль — содержательный ответ: нет продаж → выручка 0, нет событий → счётчик 0. Если же значение **невычислимо** (деление на ноль, метрика по пустой выборке), `COALESCE(..., 0)` превращает «не определено» в «всё нормально» и прячет проблему. Там честнее оставить `NULL`.

## NULLIF

```sql
NULLIF(a, b)
```

Возвращает `NULL`, если `a = b`, иначе `a`. Основное применение — защита от деления на ноль:

```sql
revenue / NULLIF(orders_count, 0)
```

Если знаменатель ноль, он становится `NULL`, и всё выражение даёт `NULL` вместо ошибки `division by zero`.

Деление на ноль — самая частая причина падения аналитического запроса на реальных данных: пустая категория, новый месяц без заказов, клиент без покупок.

---

## Доли и проценты

```sql
ROUND(100.0 * late_orders / NULLIF(total_orders, 0), 1) AS late_share
```

Три детали сразу:

- `100.0`, а не `100` — иначе целочисленное деление отбросит дробную часть;
- `NULLIF` в знаменателе;
- `ROUND(x, 1)` требует `numeric` — при необходимости добавить `::numeric`.

Прирост в процентах:

```sql
ROUND((revenue_1998 - revenue_1997) / NULLIF(revenue_1997, 0) * 100, 1)
```

## GREATEST, LEAST, ABS

```sql
GREATEST(a, b, c)   -- наибольшее из значений В СТРОКЕ (не агрегат!)
LEAST(a, b, c)      -- наименьшее
ABS(x)              -- модуль
```

`GREATEST`/`LEAST` работают по горизонтали — сравнивают колонки одной строки. `MAX`/`MIN` работают по вертикали — по множеству строк. Их легко перепутать.

**`ABS` в фильтре меняет смысл.** `ABS(deviation) > 50` ловит отклонения в обе стороны. Если в условии есть направление — «дороже», «выше», «вырос» — модуля быть не должно. Модуль уместен для поиска аномалий «в любую сторону».

## EXTRACT

Достаёт часть из даты. Возвращает число.

```sql
EXTRACT(YEAR   FROM order_date)   -- 1997
EXTRACT(MONTH  FROM order_date)   -- 1..12
EXTRACT(DOW    FROM order_date)   -- день недели: 0 = воскресенье ... 6 = суббота
EXTRACT(ISODOW FROM order_date)   -- 1 = понедельник ... 7 = воскресенье
EXTRACT(EPOCH  FROM interval)     -- интервал в секундах
```

Для «недели с понедельника» нужен **`ISODOW`**. С `DOW` неделя начинается с воскресенья, и сортировка по дням недели выйдет сдвинутой.

## DATE_TRUNC

Обрезает дату до начала периода, возвращает дату/время.

```sql
DATE_TRUNC('month', order_date)         -- 1997-03-01 00:00:00
DATE_TRUNC('month', order_date)::date   -- 1997-03-01
```

Приведение к `::date` убирает нулевое время — в отчёте так чище.

Аргумент: `'day'`, `'week'`, `'month'`, `'quarter'`, `'year'`.

### Сезонность против динамики

Это различие спрашивают на собеседованиях.

| Задача | Инструмент | Результат |
|---|---|---|
| **Сезонность**: в каком месяце года обычно выше спрос | `EXTRACT(MONTH ...)` | 12 строк, январь всех лет вместе |
| **Динамика**: как менялась выручка во времени | `DATE_TRUNC('month', ...)` | строка на каждый месяц каждого года |

```sql
-- сезонность
GROUP BY EXTRACT(MONTH FROM order_date)

-- динамика
GROUP BY DATE_TRUNC('month', order_date)
```

Если в задаче есть слова «по месяцам», «динамика», «тренд», «нарастающий итог» — нужен `DATE_TRUNC`. `EXTRACT(MONTH)` схлопнет март 1997 и март 1998 в одну строку, и график превратится в бессмыслицу.

## Арифметика дат

```sql
shipped_date - order_date        -- date - date  → integer (дней)
AGE(end_date, start_date)        -- → interval ('1 year 2 mons 3 days')
order_date + INTERVAL '30 days'
order_date - INTERVAL '90 days'
```

Разность `timestamp - timestamp` даёт `interval`, а не число. Чтобы получить дни или часы:

```sql
EXTRACT(EPOCH FROM (end_time - start_time)) / 3600 AS hours
```

### Средний интервал между событиями

```sql
(MAX(order_date) - MIN(order_date))::numeric / NULLIF(COUNT(*) - 1, 0)
```

Делить нужно на **число заказов минус один**: между 5 заказами 4 промежутка. Деление на `COUNT(*)` занижает интервал, и ошибка незаметна. `NULLIF` закрывает случай единственного заказа.

## TO_CHAR

Форматирует дату в строку:

```sql
TO_CHAR(order_date, 'YYYY-MM')      -- '1997-03'
TO_CHAR(order_date, 'DD.MM.YYYY')
```

Удобно для вывода, но результат — **текст**. Сортировка по нему лексикографическая: для `'YYYY-MM'` совпадает с хронологической, для `'DD.MM.YYYY'` — нет. Группировать лучше по `DATE_TRUNC`, а `TO_CHAR` применять только на последнем шаге, для подписи.

---

## Чек-лист ошибок

| Симптом | Причина |
|---|---|
| Месяцы разных лет слиплись | `EXTRACT(MONTH)` вместо `DATE_TRUNC` |
| Неделя начинается с воскресенья | `DOW` вместо `ISODOW` |
| `division by zero` | Нет `NULLIF` в знаменателе |
| Процент всегда целый или ноль | Целочисленное деление — нужно `100.0` или `::numeric` |
| Средний интервал занижен | Деление на `COUNT(*)` вместо `COUNT(*) - 1` |
| В выборку попали «дешевле на 50%» | `ABS` в условии с направлением |
| Сортировка по месяцам неверная | Сортировка по `TO_CHAR`, а не по дате |
| Среднее на сессию не сходится | `AVG(x) / COUNT(*)` вместо `SUM(x) / COUNT(*)` |
