SQL: ЗАДАЧИ ПО АГРЕГАТАМ И GROUP BY
База: Northwind (PostgreSQL) + users, events
Темы: COUNT, SUM, AVG, MIN, MAX, GROUP BY, HAVING

============================================================
АГРЕГАТЫ БЕЗ ГРУППИРОВКИ
============================================================

1. Количество товаров, средняя, минимальная и максимальная
   цена по всей таблице products. Среднюю округли до 2 знаков.

2. В orders: всего заказов, сколько отправлено, сколько
   не отправлено. Второе и третье получи из COUNT,
   без отдельных запросов.

3. Сколько всего пользователей в users и сколько из них
   с известным каналом привлечения. Сколько с неизвестным?

4. В events: всего событий, сколько разных пользователей
   и сколько разных сессий.

============================================================
GROUP BY
============================================================

5. Количество товаров в каждой категории,
   от большего к меньшему.

6. Количество клиентов по странам, по алфавиту.

7. Для каждой категории: количество товаров, средняя цена
   (округли до 2 знаков), цена самого дорогого товара.

8. Количество событий каждого типа в events,
   от частых к редким.

9. Количество регистраций по каналам привлечения.
   Проверь, попала ли в результат группа с NULL,
   и объясни почему.

10. Количество событий по дням: event_time::date под алиасом
    day и количество событий за этот день. По возрастанию
    даты, первые 7 дней.

============================================================
GROUP BY ПО НЕСКОЛЬКИМ ПОЛЯМ
============================================================

11. Количество пользователей по паре «страна + устройство».
    Сортировка по стране, внутри по количеству по убыванию.

12. Количество заказов по паре «страна доставки + год заказа».
    Год: EXTRACT(YEAR FROM order_date).
    Сортировка по стране, внутри по году.

============================================================
HAVING
============================================================

13. Страны, в которых больше 5 клиентов.

14. Категории, где средняя цена товара выше 30
    и при этом товаров не меньше 5.

15. Пользователи (user_id) из events, у которых больше
    10 событий. Топ-20 по количеству.

16. Сессии, в которых было больше 5 событий:
    session_id и количество. Топ-10.

============================================================
ПОСЛОЖНЕЕ
============================================================

17. По order_details для каждого заказа: итоговая сумма
    (unit_price * quantity * (1 - discount), округли)
    и количество позиций. Только заказы дороже 5000,
    топ-10 по сумме.

18. По order_details для каждого товара: сколько всего единиц
    продано и в скольких разных заказах он встречался.
    Топ-10 по проданным единицам.

19. По events для каждого товара количество просмотров
    (view_product), топ-10. Фильтр по типу события идёт
    в WHERE, а не в HAVING.

20. По orders за 1997 год для каждого клиента: количество
    заказов, количество отправленных заказов и среднее время
    доставки в днях (shipped_date - order_date).
    Только клиенты минимум с 5 заказами, сортировка
    по среднему времени доставки по убыванию.
    Подумай, что происходит с неотправленными заказами
    при подсчёте среднего.
